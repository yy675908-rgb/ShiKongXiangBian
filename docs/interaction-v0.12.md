# 0.12 操作与流畅度

本次保留已有分析顺序、能量本质、应事路径、排序与原始记录内容，调整运行方式和操作流程。

- 排盘、逐层分析、人事翻译在后台计算；加载中有反馈。取消旧请求并核对请求编号，快速点击前后一天时旧结果不能覆盖新日期，加载或结果过期时不能保存实际经过。
- 手输日期先作为草稿，点“查看”或键盘完成后应用，避免每输入一个字符就重新分析。原生日期/时间选择、此刻、前后一天减少输入。严格校验真实日期与时分，拒绝 2 月 30 日、24:00 和未来出生时间；未来预测日期仍可使用。日期草稿不同于当前结果时明确指出当前分析时间。
- 本命编辑先保留草稿，校验并保存后才影响分析。首次打开直接进入本命设置；改动未应用时不展示冒充新设置的旧本命预览。
- 三个页面分别保存滚动位置；展开状态可恢复。逐层与应事卡片独立按需加载并使用稳定键与内容类型，避免一个长列表项一次性布局所有事项。完整记录分段解析和展开推导使用缓存。
- 计算会话使用 ViewModel，旋转时保留正在进行的计算和保存。实际经过与勾选按完整预测输入分开保存，会话内切换日期可恢复各自草稿；当前表单使用 SavedStateHandle 支持系统状态恢复。完整历史不再塞入 saved-instance-state。
- 核对、完整记录拼接及历史索引在后台整理，记录和校正记忆在同一次 SharedPreferences 提交中写入。保存过程拦截重复操作，保存期间新增输入不清空；失败保留草稿，成功提示可直达最新记录。切换日期期间完成的保存仍记在提交时的原日期。
- 核对事项整行可点击，触摸区域至少 48 dp。键盘避让用于页面输入，应用日期、保存本命和实际经过时收起键盘。

验证：项目 Kotlin 2.0.21 执行 `testDebugUnitTest assembleDebug` 通过，57 项测试、0 失败、0 错误，生成 0.12.0（versionCode 12）调试包。新增测试覆盖真实默认排盘/分析结果一致、严格日期、恢复草稿、迟到旧任务、加载时禁止保存、重复提交、保存期间新输入保留、按日期保留草稿、失败重试、跨日期保存和重复旧记录的稳定键。原有 49 项分析测试继续通过。

尚未执行设备上的 UI 点击、旋转与系统重建测试，也未测量帧率、启动时间或低端设备手感；测试通过证明计算与状态协调结果，不代表已完成真机性能验收。

实现参考 Android 官方 [Compose 性能建议](https://developer.android.com/develop/ui/compose/performance/bestpractices) 与 [生命周期协程](https://developer.android.com/topic/libraries/architecture/coroutines)。

## 安装包整理

GitHub 原有 0.6 APK 与最新 0.12 APK 的实际签名证书不同，不能作为同包覆盖更新。调试交付版使用独立包名 `com.shikongxiangbian.app.preview`，图标名称“时空象变·新版”，可与旧版并存，无需卸载旧版。旧记录仍留在旧版，新版需要重新设置本命；不宣称已自动迁移数据。正式 release 包名保留原值。

最终构建日志另显示旧工作流的签名缓存路径不存在，缓存没有保存，导致连续构建证书不同。现通过 `SHIKONG_DEBUG_KEYSTORE` 显式指定 Gradle 调试签名文件为工作区 `.ci-signing/debug.keystore`，工作流先恢复同一路径缓存，仅在缺失时生成密钥，构建后核对公开证书并保存缓存；使用新缓存键 v2。签名目录已排除出 Git。密钥不写入源码，不公开下载。第一次建立新密钥后，后续更新需继续保留该缓存/密钥。
